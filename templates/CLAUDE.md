# Jev 라우팅 정책 (Claude Code)

`~/.codex/AGENTS.md`의 Jev 우선 정책을 Claude Code 도구 이름에 맞춰 옮긴 것이다.
CLI는 `~/.local/bin/`에 있고 `~/.local/share/codex-token-tools/`를 공유한다 — 에이전트 중립이므로 Codex와 같은 것을 쓴다.

## 기본 원칙

작은 작업은 요청·대상·검증만 정해 바로 처리한다. 사실·캐시·종료코드는 코드로 얻고, 복잡한 작업만 최대 5단계로 계획한다.
기존 지침·Git 변경을 보존하고 필요한 설정만 확인한다. 같은 조사·캐시·출력을 모델에 반복 입력하지 않는다.

**모든 별도 선택형 의미 판단은 Jev에 먼저 맡긴다.** 사실 확인·코드 작성·필수 분석·안전 정책은 그대로 모델이 유지한다.
Jev가 UNKNOWN을 반환하면 그것을 모델 결론으로 바꾸지 않는다. 실패·차단을 우회하지 않는다.

## 판단 위임

| 상황 | 명령 |
| --- | --- |
| 파일에 대한 선택형 판단 | `jev-judge --file 경로 --question 질문` |
| 시각 확인·구현 선택 | `jev-visual --spec 경로` (픽셀 확인·코드 생성은 지원 도구로) |
| 데이터 수집·선별 | `jev-collect --spec 경로` → `--read manifest --cursor N` |
| 검증·불명 셸 실행 | `jev-verify plan --spec 경로` → `run --spec 경로 --execute` |
| 코드 충돌 판단 | `jev-conflicts` |

원문·출처·UNKNOWN·오류·제약은 항상 보존한다. 결과 판정도 Jev에 맡기고, 원본 로그·종료코드를 조작하지 않는다.

## 판단은 남기고 텍스트로 발행하지 않는다 (jev-mode)

경계 있는 의미 판단이 **5개 이상** 반복되면 그걸 내 컨텍스트에서 결정하지 않는다. 자세한 절차는 `jev-mode` 스킬.

- **항목 텍스트를 컨텍스트에 들이지 않는다.** 코드로 읽고, 코드로 요청을 만들고, **개수만 출력한다.** 절감의 대부분이 여기서 나온다.
- 호출당 레코드 하나. 배열 state는 하나의 읽기로 뭉개진다.
- 여러 atomic 질문을 argmax로 재조합하지 말고, **짧고 결정적인 규칙을 담은 `choice` 질문 하나**를 쓴다.
- 답의 조합(가중치·임계값)은 코드가 소유한다. confidence가 낮으면 조용히 수용하지 말고 더 날카로운 criteria로 2차 패스한다.
- 쓰지 않는 것: 산문, 코드 작성, 설명, 산술, 개수 세기, 크기 비교, 날짜 비교.

**서브에이전트는 pre-action 훅을 받지 않는다**(측정됨). 호스트 훅의 게이트는 내 세션만 보호하고 자식은 보호하지 않는다. 자식에게는 좁은 작업을 주고 단계마다 Jev 호출을 요구한 뒤, 끝나고 검증한다.

## 출력 규율 — 토큰의 77%가 여기서 나간다

측정값(2026-09-20): Messages 206k / System tools 24k / MCP 22k / Skills 10k.
**MCP·스킬을 전부 지워도 12%다.** 비용은 도구 출력이므로 규율도 거기에 건다.

- **넓은 탐색은 `Agent`(Explore)에 위임한다.** 서브에이전트는 결론만 돌려주고 파일 덤프는 내 컨텍스트에 안 남는다. 여러 파일·디렉터리를 훑어야 답이 나오는 질문이면 직접 읽지 말고 위임한다. 파일·심볼을 이미 아는 단건 조회만 직접 한다.
- **조회·Git·검색 출력은 명령마다 `head -c 4000` / `tail -c 4000`.** 목록은 `head -N`으로 자른다.
- **`Read`는 필요한 구간만** — 파일 전체를 읽지 말고 `offset`/`limit`을 쓴다.
- **편집 후 재확인 금지.** 실패했으면 Edit/Write가 에러를 냈다. 하네스가 파일 상태를 추적한다.
- **이미 컨텍스트에 있는 내용을 다시 붙여넣지 않는다.** 같은 조사·캐시·로그를 반복 입력하지 않는다.
- **원문 대신 판단을 남긴다** — 경계 있는 판단 5개 이상이면 위 jev-mode 규칙.

## 서브에이전트 모델 라우팅

**부모 모델을 자식이 그대로 물려받으면 비싸다.** Fable 5.1/Opus로 울트라코드·워크플로를 돌릴 때
에이전트 다수가 부모 티어로 떠서 소모가 급증한다. 그래서 티어를 명시한다.

- `~/gameforge/plugins/gameforge/agents/*.md`의 `model:`은 Jev 판단으로 고정돼 있다
  (game-designer=opus, 나머지 4개=sonnet). `inherit`로 되돌리지 않는다.
- **정의가 없는 일회성 `Agent` 호출은 `model`을 명시한다.** 판단이 서면 Jev에 묻는다:
  ```sh
  jev-mode ask --state-file <작업설명파일> --questions-file ~/.claude/jev/agent-tier.json
  ```
  haiku=절차 실행·관찰·대조 / sonnet=구현·리뷰·규칙적용 / opus=충돌하는 제약 속 설계·되돌리기 어려운 방향 결정.
  confidence가 0.7 미만이면 조용히 수용하지 말고 더 날카로운 기준으로 2차 패스한다.
- **`subagent_type: "fork"`는 `model`이 무시된다** — 포크는 항상 부모 모델을 쓴다. 비싼 부모일 때 포크를 남발하지 않는다.

## 검색

좁은 검색(알려진 파일·정확한 심볼·작은 작업)은 `Grep`/`rg`.
**많은 구절이 나올 넓은 관련성 검색은 `mcp__jev_context__search_code`** — ripgrep 후보를 컨텍스트에 넣기 **전에** Jev가 걸러 Yes만 돌려준다. 자세한 규칙은 `jev-code-search` 스킬.
- 걸러지지 않은 검색을 먼저 돌리고 그 결과를 넘기지 않는다 — 절감이 사라진다.
- `repository_root`는 매 호출 절대경로로 명시한다. 서버 작업 디렉터리나 이전 작업에서 추론하지 않는다.
- 빈 결과는 "통과한 후보 없음"이지 "증거 없음"이 아니다. 질의·목표를 다듬는다.
무관한 파일·생성물·의존성은 제외한다.

## 브라우저·UI 조작

브라우저는 활성 `aside-browser`를 우선한다.
허용된 **반복** 조작은 `jev-action-control` 스킬의 Aside·macOS·iOS 실행기에 이양한다. 판단만 요청받았으면 실행하지 않는다.
정확성·기능·테스트·안전성·필수 분석은 유지한다.

## 서브에이전트 위임

모든 서브에이전트·Aside 위임에 이 규칙과 작업 범위·결과 형식을 직접 전달한다.
전체 이력 대신 필요한 파일·사실만 준다. 판단은 선택값으로, 작업은 변경·검증·주의만 받는다.
기존 자식에게도 갱신 규칙을 전달하고, 위반·누락 시 필요한 부분만 보정한다.
관련 수정·가까운 검증을 묶으며, 설명·최종 보고에 원문·로그·반복 해설을 넣지 않는다.

## Claude Code에서 쓸 수 없는 것 (Codex 전용)

- **`jev-session-read`** — Codex rollout JSONL(`response_item`) 스키마 전용. Claude Code transcript(`~/.claude/projects/*/*.jsonl`)에 대해서는 오류 없이 **0 records**를 반환하므로 "확인했다"고 착각하기 쉽다. 쓰지 않는다.
- **`jev-browser-use`** — `cua_repl` 런타임을 요구한다. Claude Code 브라우저 연동은 미지원.
- **`jev-codex` / `jev-gateway-codex`** — Codex 모델 라우터·툴 게이트웨이. Claude Code에는 해당 경로가 없다.

## 기능 토글

`~/.local/share/codex-token-tools/features.json`; `jev-features disable <기능명>`으로 끈다.
